# Анализ боевых логов → исправления 1.17

Два приложенных лога: `Сканировать выбранные.txt` (~730 строк) и
`Сформировать документы.txt` (~250 строк). Ниже — что в них было не так
и что исправлено.

## 1. Сканировать выбранные

| # | Симптом в логе | Диагноз | Исправление |
|---|---|---|---|
| 1 | `HTTP 404 (3 раз)` грозы при пагинации | 404 — нормальный конец пагинации, а не ошибка | 404 без счётчика и без браузера (было в 1.15; подтверждено) |
| 2 | `❌ topic filter: ... | Ошибка на странице` | фильтр тем глушил исключения без деталей | сообщение с типом ошибки (было в 1.16.x) |
| 3 | `⚠️ errors: 254` при 0 реальных ошибок | счётчик считал технические записи | раздельные счётчики ошибок/предупреждений (было в 1.16) |
| 4 | `fast_fetch ... Погрешность: 0.0` — сотни строк | шум без пользы | оставлено только в debug (1.16); в 1.17 добавлена статистика транспорта |
| 5 | Порча Cookie после `cookie_harvest` | `Cookie2`/сырые строки из браузера ломали jar | канонизация jar при каждом запросе (`_canonical_cookie_header`) |
| 6 | `login_form` при живой сессии | один общий отказ без деталей | разделение `redirect_login` / `login_form`, дампы HTML в `logs/fast_refused/` |
| 7 | harvest → вечный браузер | куки забрали, но fast не повторялся | harvest-retry: повтор через fast после деплоя |
| 8 | Фиксированный cooldown 300 с | долгий простой при глитчах | адаптивное окно 300→600→1200→1800 со сбросом при успехе |
| 9 | `Отчет по темам` попап после этапа | мешает, теряется при закрытии | удалён; кнопка **📜 История** с бейджем + вечный журнал |
| 10 | `Сканировано: 0 разделов` в итоге | plural-баг + нечестный итог | plural-формы + честный счётчик просканированных разделов |

## 2. Сформировать документы

| # | Симптом в логе | Диагноз | Исправление |
|---|---|---|---|
| 1 | `Изменений: 0` при изменившемся checksum | diff молча пустовал, если менялись только автор/дата/картинка | МЕТА-диагностика: diff всегда объясняет причину |
| 2 | `🖼 Изображение`, `🖼 Изображение #1` — нумерация с нуля | счётчик начинался с 0, дублей не было видно | сквозная нумерация с 1, дедуп по URL, негативный кэш |
| 3 | OCR на каждый чих | движок дёргался даже на иконках 16×16 | гейты: < 1500 байт и < 24×24 пропускаются |
| 4 | Один и тот же OCR по кругу | не было кэша по содержимому | кэш SHA-256 → текст (`images/.ocr_cache.json`) |
| 5 | Подвисшие спиннеры на пропущенных картинках | пропуску не ставился финальный статус | пропуск = `skipped`, спиннер гаснет всегда |
| 6 | `100%` при `120/100` шагов | прогресс-бар врал | кламп значения в `[0, total]` |
| 7 | `Найдено N постов` без склонений | «1 постов», «2 пост» | `plural()` во всех пользовательских строках |
| 8 | Всплывающий `Отчет` в конце генерации | та же проблема, что п.9 выше | удалён; события пишутся в **📜 Историю** |

## 3. Подтверждено корректным (не трогали)

- Трёхслойный DOCX (правила сервера / сообщение / общие правила), хвост
  «В конце ответа всегда пиши…» отсутствует — паритет со сканом (тест X1).
- Сканирование пагинации тем, фильтр гайдов, `thread_dates.json`.
- Очередь UI (`ProcessEmitter`), потоковая архитектура этапов.
- Дедуп-history: 7 «Изменилась» на одну тему за один прогон больше
  невозможен (дедуп по checksum + виду события).
