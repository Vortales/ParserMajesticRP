# ultiparser 1.16

Полный код парсера форума Majestic RP, версия **1.16**.
Папка автономна: скрипт хранит все рабочие файлы рядом с собой, внутри `ultiparser1.16/`.

Главное новшество — **гибридный транспорт запросов**: сначала быстрый путь
напрямую через `requests` с cookies авторизации (как у разработчика, парсившего
«напрямую по кукам»), при любых проблемах — автоматический фолбэк в проверенный
браузерный движок 1.15. Структура результатов, состав кнопок/панелей GUI и порядок
слоёв в документах — **без изменений**.

## Что изменилось относительно 1.15

**1. Быстрый путь запросов (⚡) — парсинг напрямую по cookies.**
Каждый запрос сначала идёт через лёгкую `requests`-сессию с keep-alive,
cookies из «🔑 Войти» и браузерными заголовками (UA собирается из версии
реального Chrome, `Sec-Fetch-*`, `Accept-Language`). Только если быстрый путь
не справился — страница уходит в браузерный движок 1.15 без изменений.
Браузер при этом стартует лениво: если все страницы берутся быстрым путём,
тяжёлый Selenium может вообще не понадобиться до Этапа 2.

**2. Антибот-аккуратность (важно!).**
Форум чувствителен к нагрузке: агрессивный опрос ведёт к детекту и блоку
примерно на 10 минут. Поэтому быстрый путь умышленно «вежливый»:
- глобальный лимитер: минимум **1,2 с** между запросами всех потоков + джиттер;
- пауза **1,2–2,8 с** перед каждым быстрым запросом (в браузере было 3,5–7 с);
- адаптивный бэк-офф до ×4 при ошибках, затухающий на успехах;
- после **3 блокировок подряд** — режим «только браузер» на 5 минут;
- проверка каждого быстрого ответа: HTTP 200, не редирект на `/login`,
  нет формы входа, нет антибот-маркеров, у тем — наличие постов
  (подозрительная «пустая» тема перепроверяется через браузер, а не молча принимается).

**3. Самовосстановление cookies.**
После браузерных успехов на фоне страдающего быстрого пути парсер
забирает свежие cookies из браузера и подливает их в сессии; окно
«только браузер» при этом сокращается до 60 секунд.

**4. Новый индикатор в GUI.**
- Чекбокс **«⚡ Быстрый путь (cookies)»** в «Глобальных настройках»
  (сохраняется в `config.json` как `fast_path_enabled`, по умолчанию включён).
- Живая строка транспорта вместо статичной подписи: счётчики
  `⚡ fast N · 🌐 browser M`, предупреждение при слетании авторизации,
  обратный отсчёт режима «только браузер».

Состав кнопок и панелей не менялся: `🔑 Войти` → `🔍 Сканировать` (Этап 1) →
пометки/чекбоксы → `Этап 2` → `🚀 Сформировать документы`.

**5. Ускорение мелочей без смены логики.**
Кэш `thread_dates.json` в памяти с защитой по mtime, regex-предфильтр даты
создания темы вместо полного парсинга каждой страницы, скачивание картинок
форума быстрой сессией до прокси/браузера.

**6. Исправлены два бага 1.15 (без смены поведения в остальном).**
- Счётчик «Готово» (done) теперь учитывает пропущенные темы
  (битые ссылки и уже готовые из кэша) — прогресс доходит до 100%.
- Слияние деревьев (`merge_preserve_state`) больше не смешивает пометки
  «Общие/Сервер» между якорными категориями (`/#...`) одной страницы:
  раньше все якоря схлопывались в один ключ и получали пометку одного
  произвольного якоря.

**7. Версия в интерфейсе:** заголовок окна и стартовый баннер показывают `1.16`.

Порядок слоёв в документах — как в 1.15: **ОБЩИЕ ПРАВИЛА → ЗАКОНОДАТЕЛЬНАЯ БАЗА
сервера → ПРОМТ в самом низу**, хвоста `===КОНЕЦ ОТВЕТА===` нет.

## Быстрый старт

1. Перенесите данные из 1.15 (один раз):
   ```
   cd ultiparser1.16
   python migrate_data.py
   ```
   Скрипт скопирует структуру форума, галочки, пометки «Общие/Сервер», конфиг,
   cookies, даты тем и файл промта. Папку `Результаты/` он по умолчанию пропускает —
   документы пересоздадутся кнопкой «Сформировать документы».
   Если нужны и старые docx: `python migrate_data.py --with-results`.
   Можно мигрировать и напрямую из 1.14.
2. Запустите парсер:
   ```
   python ultiparser1.16.py
   ```
   Зависимости (`requests`, `beautifulsoup4`, `python-docx`, `lxml`, `selenium`)
   ставятся автоматически при первом запуске. Нужен Google Chrome и кнопка
   «🔑 Войти» (cookies от входа питают быстрый путь).
3. Быстрый путь активен, когда: чекбокс «⚡ Быстрый путь» включён **и**
   загружены cookies (кнопка «🔑 Войти»). Без cookies всё работает через
   браузер, как в 1.15.

## Рекомендации по скорости и безопасности

- Не поднимайте «Потоки» выше **4** и не жмите «🔑 Войти» часто —
  это главный триггер антибота (детект → блок ~10 минут).
- Если строка транспорта показывает растущий `🌐 browser` при нулевом `⚡ fast`
  и предупреждение про вход — обновите cookies кнопкой «🔑 Войти»
  (один раз, не чаще раза в несколько минут).
- При нестабильном интернете быстрый путь сам уйдёт в браузер и вернётся —
  вмешиваться не нужно; чекбокс «⚡» — только аварийный выключатель.

## Как проверялась версия 1.16

- `py_compile` — успешно.
- 11 тестов гибридного транспорта со стабами сети/браузера (`/tmp/t116/test_transport.py`):
  быстрый хит без обращения к браузеру, фолбэк при 403/429, режим «только браузер»
  после серии блоков, редирект на `/login`, подозрительная тема → браузер,
  страница ошибки → принять как есть, merge cookies с пересборкой сессий,
  сбор cookies из браузера с сокращением окна, ленивый старт браузера,
  выключенный fast, параллельный рейт-лимитер держит интервал.
- Тесты паритета (`/tmp/t116/test_parity.py`): merge якорей хранит свои пометки,
  кэш дат по mtime + инвалидация через save, regex/soup паритет дат создания тем,
  сквозной `python-docx`: слои `ОБЩИЕ → БАЗА → ПРОМТ`, промт последний, хвоста нет.
- `diff` 1.15 vs 1.16: только задуманные изменения (см. `АЛГОРИТМ.md`, раздел 7).
