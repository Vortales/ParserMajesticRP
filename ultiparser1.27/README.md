# ultiparser 1.27 — конвейер 1→2→3 + JSON-темы

Полный парсер на Tkinter: сканирование структуры форума Majestic RP →
скачивание тем → формирование DOCX (правила сервера / правила гос. структур).

## Новое 1.27: конвейер, JSON-темы, clean-копии

Панель «Конвейер»: Этап 2 (сканировать выбранные) и Этап 3
(сформировать документы) — по одному или «▶ Выполнить всё (2→3)»:
серверы выбираются один раз, Этап 3 стартует сам после Этапа 2
(прерывается «Стоп»/ошибкой). «Ключевые слова» — отдельный
фильтр (не этап), Этап 1 («Сканировать» + ручные пометки) в
конвейер не входит. Под структурой — тумблер «🚫 Искл.: ВКЛ/ВЫКЛ»
(временно гасит исключения структуры на сессию, только показ).

Темы в папках «Темы» хранятся в едином JSON (`ultiparser-topic/1`:
мета + посты + sections для будущего внешнего поиска) вместо
per-topic .docx; одноимённые legacy-.docx удаляются при перезаписи.
Рядом с каждым итоговым документом — `clean_`-копия без
форматирования (абзацы как после парсера). В «Темы» остаются только
отмеченные «Выбор» (остальные файлы удаляются, чужие не трогаем).

История: серверная тема больше не попадает в «Общие» — приоритет
сервера при кросс-листинге, свежие слои заменяют записанные,
показ всегда сверяется с текущими пометками. Отмеченная тема видна
в структуре даже под исключениями («импостеры» больше не прячутся),
а скрытие/возврат больше не сдвигают объекты. Ctrl+C копирует
из любого текстового виджета (без выделения — всё содержимое).

Правка: автоотметка тем смотрит ТОЛЬКО на слова тем — широкие слова
разделов («Правила», «Суд»…) больше не отмечают чужие темы после
Этапа 2. Перестроение дерева чистит отсоединённых сирот и показывает
ошибки явно, а не молча.

## Исправление 1.26 (из 1.26): серверные темы больше не падают в «Общие»

Причина: события «найдена/пропала» (Этап 2) писались в историю
без слоёв, а тема без слоёв показывалась в «Общих» по умолчанию —
туда и сыпались серверные темы. Теперь слои ставятся при записи
по пометкам структуры (`_thread_scopes_by_url`: под «Общими» →
general, под корневым «Сервером» → server:<имя>), а для старых
записей без слоёв слой выводится при открытии окна из текущих
пометок — пересоздавать историю не нужно.

Правая панель «Истории» — одна, но изменения в ней идут таблицей
с границами: после шапки `[Пост #, автор…]` начинается таблица
`┌ БЫЛО ┬ СТАЛО ┐`, строки «было» и «стало» сопоставлены друг другу
попарно, дальше новая дата — новая таблица. В таблицу попадают только
diff-строки, префиксы «БЫЛО:/СТАЛО:» убраны (их заменяет шапка),
левая колонка красная, правая зелёная, длинные строки переносятся
с сохранением границ. Горизонтальный скролл — под панелью.

## Новое 1.25 (из 1.25): «Исключения структуры»

Рядом со строкой поиска под «Структурой форума» — кнопка
«🚫 Исключения…»: отдельный список слов (не связан со списками
автоотметки и «Истории»). Темы с этими словами в названии скрываются
из дерева — мусор вроде «Исковое заявление» больше не маячит.
Исключение ищется в теме И разделе; счётчик показывает
`Тем: N · скрыто: M`; ветки, где скрыто всё, сворачиваются целиком,
непросканированные разделы не трогаем. Скрытие — только визуальное:
галочки, скачивание и документы не меняются (снимать отметки —
по-прежнему дело списка «не отмечать» в автоотметке).

## Исправление 1.24 (из 1.24): корень бага с исключениями

Симптом 1.23: темы исключённого раздела всё равно с галочками —
на всех уровнях (Раздел/Подраздел/Ур.3/Ур.4/Ур.5+). Корень: Этап 2
завершается функцией «восстановления по снимку ДО сканирования»,
которая поверх результатов скана возвращала старые отметки
и ставила новые по ключевым словам — полностью мимо исключений,
обнуляя фиксы 1.22–1.23. Теперь финальное решение идёт через
`final_thread_check_value` (исключение бьёт всё), в логе
`⏭ Снято отметок (исключения, финал): N`, а в отчёте «Этап 2»
видны переходы `True → False`. Заодно починен рестор при старте:
тоже уважает исключения и синхронизирует модель (был рассинхрон).

## Исправление 1.23 (из 1.23): три вещи

**1. Исключения работают везде, а не только на Этапе 2.** Баг 1.22:
Этап 2 галочки снимал, но клик по разделу, кнопка «Все» и даже
восстановление состояния при запуске ставили их обратно — мимо
исключений. Теперь отметка раздела пропускает исключённые темы;
нажатие «Сохранить» в ключевых словах снимает такие галочки сразу,
без рескана (`🚫 Исключения применены: снято N`). В начале Этапа 2
в лог пишется, какие исключения активны (или предупреждение, что их нет).

**2. «История» пишет только отмеченные темы.** Раньше записывались все
найденные; теперь — только с галочкой «Выбор», остальные пропускаются
(в логе: `пропущено неотмеченных: M`). Раскладка окна: общие темы всегда
сверху, дальше разделитель `── 🖥 Сервер «X» ──` и только темы выбранного
сервера — чужие серверы больше не мешаются. Переключатель слоёв убран.

**3. Поиск под «Структурой форума».** Строка 🔍 как в «Истории»: фильтрует
дерево по темам и разделам на лету, счётчик «Найдено тем: N».

## Исправление 1.22 (из 1.22): исключение раздела глушит темы внутри

Баг 1.21: если раздел (например, «Отмененные законопроекты») добавлен
в «🚫 Исключения», а тема внутри подходит под ключевое слово («Закон»),
уже стоящая галочка НЕ снималась при Этапе 2 — проверка исключений
просто пропускала тему, оставляя старое значение.

В 1.22 исключение проверяется первым и бьёт всё: галочка снимается
(и старая, и ручная), новая не ставится. В логе видно
«⏭ Снято отметок (исключения): N». Проверка идёт и по названию темы,
и по названию раздела — как написано в окне («есть в теме/разделе»).

## Антипалево 1.21 (из 1.21): форум больше не банит за шторм ретраев

Симптом 1.20: на 4 потоках форум отвечал `Page could not be loaded`
и закрывал доступ на 10+ минут. Причина: быстрый канал не знал про
паузу браузерного, и 4 потока × 2 канала долбили форум ретраями
прямо во время блокировки — продлевая её.

Что делает 1.21:

- **общий рубильник**: 2 блок-сигнала подряд (403/429/антибот/chrome-error
  с любого канала) останавливают ВСЕ потоки и ОБА канала сразу;
  паузы эскалируются 60 → 120 → 300 → 600с; 15 чистых хитов подряд
  сбрасывают эскалацию; индикатор «⏸ форум отдыхает М:СС»;
- **«Стоп» прерывает и паузы**: все ожидания идут квантами по 2с
  с проверкой кнопки (раньше «Стоп» висел до конца 3–5-минутной паузы);
- **🐢 Тихий режим** (чекбокс, сохраняется): все паузы ×3 —
  включается после бана, выключается когда форум «отпустил»;
- **мягкий предел потоков 2** (было 4): больше — с предупреждением
  про риск бана и советом включить тихий режим.

Правило выживания: потоки 1–2 + тихий режим после первого же
«форум отдыхает». Скорость ниже, но доступ не закрывается.

## Почему всё время браузер (разбор, из 1.20)

Факты из лога: куки отправляются (`cookies: 8, xf_user: есть` — это
доказано и тестом), но форум каждый раз присылает страницу с формой
входа. Возможны две причины:

1. **Сессия мертва на стороне форума.** Файл cookies выглядит живым
   (`xf_user` есть, срок в будущем), но remember-токен уже не признаётся
   сервером — и каждый быстрый запрос получает гостевую страницу.
   Лечение: свежий «🔑 Войти» **с галочкой «Запомнить меня»**, затем
   «🍪 Проверить cookies» должен показать «Быстрый путь РАБОТАЕТ».
2. **Форма входа встроена в тему оформления.** Страница на самом деле
   ваша (есть меню аккаунта и контент), но детектор видел форму входа
   и браковал страницу. Это чинится само в 1.20 (см. ниже).

Что делает 1.20 для обоих случаев:

- **доверие маркерам входа**: если на странице есть сильные маркеры
  (меню аккаунта, ссылка выхода) И ожидаемый контент (темы/посты),
  страница принимается быстрым путём, а форма игнорируется
  (`…КБ (маркеры входа есть, форма проигнорирована)`); счётчик
  `fast_trusted` в статистике транспорта;
- **разбор каждого отказа**: в причине теперь видно
  `маркеры входа: нет / только слабые / есть, но нет контента`,
  в лог пишется заголовок страницы;
- **полные дампы** `logs/fast_refused/*.html` (было 8 КБ) с разбором
  в шапке — отказавшую страницу можно открыть в браузере и увидеть
  глазами, что прислал форум;
- **«🍪 Проверить cookies»** тоже умеет доверять маркерам и показывает
  разбор (заголовок, число маркеров, контент).

Безопасность: гостевая страница без маркеров по-прежнему идёт
в браузер; страница с маркерами, но без контента — тоже (защита
от «нет прав»).

## Фильтры ключевых слов

У каждого слова для тем и разделов теперь два фильтра:

- **☑ целое** — «закон» выбирает «Закон "О…"», но игнорирует
  «законодательство» и «законопроект»;
- **позиция**: «везде» / **«в начале»** / «в конце» —
  «закон "О…"» подходит, а «тут закон» — нет (для «в начале»).

Старые настройки (просто слова) работают как раньше: подстрока, везде.
Исключения (1.19) оставлены широкими специально: там широта = надёжность.

## Быстрый старт

```bat
cd ultiparser1.26
python ultiparser1.26.py
```

Зависимости ставятся сами при запуске (нужен Chrome).

## Перенос данных из 1.26

```bat
cd ultiparser1.27
python migrate_data.py            :: ищет ultiparser1.26 рядом
python migrate_data.py --src <путь к ultiparser1.26>
```

Копируются структура, чеки, конфиг, куки, даты тем, **история**,
кэш и картинки. Также умеет мигрировать напрямую из 1.14–1.25.

## Тесты

```bat
cd ultiparser1.27\tests
python test_transport.py    :: T1–T15 (+trust-markers, analyze, breaker, stealth)
python test_features.py     :: plurals, история (H1–H6/H8/H9), исключения (E1/E3),
                            :: матчер слов (E2), скрытие структуры (E4/E5),
                            :: diff, картинки, OCR, docx (X1–X3),
                            :: JSON-темы (J1/J2), снапшот скрытия (R1), стражи
```
