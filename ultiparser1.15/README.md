# ultiparser 1.15

Полный код парсера форума Majestic RP, версия **1.15**.
Папка автономна: скрипт хранит все рабочие файлы рядом с собой, внутри `ultiparser1.15/`.

## Состав папки

| Файл | Назначение |
|---|---|
| `ultiparser1.15.py` | Полный код парсера (запуск: `python ultiparser1.15.py`) |
| `migrate_data.py` | Перенос данных из 1.14 (структура, галочки, конфиг, куки, даты тем, промт) |
| `АНАЛИЗ_ОШИБОК.md` | Разбор кода: что проверено, потенциальные места внимания (код рабочий, логика не менялась) |
| `README.md` | Этот файл |

## Что изменилось относительно 1.14

**1. Промт (слой 1) переехал в самый низ документа — под слой сервера.**

Было (1.14):

```
1. ПРОМТ
   ════════════════════════════════════════════════════════════
2. ОБЩИЕ ПРАВИЛА (правила проекта)
   ════════════════════════════════════════════════════════════
3. ЗАКОНОДАТЕЛЬНАЯ БАЗА: <сервер>
   «В конце ответа всегда пиши ===КОНЕЦ ОТВЕТА=== ...»
```

Стало (1.15):

```
2. ОБЩИЕ ПРАВИЛА (правила проекта)
   ════════════════════════════════════════════════════════════
3. ЗАКОНОДАТЕЛЬНАЯ БАЗА: <сервер>
   ════════════════════════════════════════════════════════════
1. ПРОМТ  ← самый низ, чтобы ИИ точно держала его в памяти
```

В файле «Общие правила.docx» аналогично: сначала общие правила, промт — в самом низу.
Выбор тем 3-го слоя, как и раньше, зависит от чекбоксов в дереве (кнопка «Сформировать документы»
собирает только отмеченные темы выбранных серверов).

**2. Удалён добавочный хвостовой шаблон** `«В конце ответа всегда пиши ===КОНЕЦ ОТВЕТА=== ...»`
в конце генерируемых документов. Это безопасно: требование писать `===КОНЕЦ ОТВЕТА===`
уже содержится в самом промте (`promt 1.5.txt`), а теперь промт идёт последним и ИИ его точно видит.

**3. Автономная папка версии.** `SERVERS_ROOT` больше не привязан к имени `ServerParser`
и к текущей директории запуска — все данные (`forum.majestic-rp.ru/`, `logs/` и т.д.)
создаются рядом со скриптом. Версии 1.14 и 1.15 никак не мешают друг другу.

**4. Версия в интерфейсе:** заголовок окна и стартовый баннер показывают `1.15`.

Вся остальная логика (авторизация, Этап 1 / Этап 2, фильтры, OCR, кэш, сверка изменений,
генерация docx) — **без изменений**, один в один как в рабочей 1.14.

## Быстрый старт

1. Перенесите данные из 1.14 (один раз):
   ```
   cd ultiparser1.15
   python migrate_data.py
   ```
   Скрипт скопирует структуру форума, галочки, пометки «Общие/Сервер», конфиг,
   cookies, даты тем и файл промта. Папку `Результаты/` он по умолчанию пропускает —
   документы пересоздадутся кнопкой «Сформировать документы» уже с новым порядком слоёв.
   Если нужны и старые docx: `python migrate_data.py --with-results`.
2. Запустите парсер:
   ```
   python ultiparser1.15.py
   ```
   Зависимости (`requests`, `beautifulsoup4`, `python-docx`, `lxml`, `selenium`)
   ставятся автоматически при первом запуске. Для сканирования нужен Google Chrome
   и кнопка «🔑 Войти» (как в 1.14).
3. Если путь к промту подсветился как ненайденный — выберите файл промта заново
   кнопкой «📄 Выбрать» в блоке «Глобальные настройки».

## Как проверялась версия 1.15

- `py_compile` обоих файлов — успешно.
- Юнит-прогон функций `build_server_docx` / `build_common_docx` со стабом:
  порядок `ОБЩИЕ → БАЗА → ПРОМТ`, промт последний, хвоста нет, пустой промт
  не добавляет лишний разделитель.
- Сквозной тест с настоящим `python-docx`: сгенерированы `server.docx` и `common.docx`,
  порядок абзацев в файлах соответствует новой схеме слоёв.
- `diff` 1.14 vs 1.15: только задуманные изменения (версия, корень данных, порядок слоёв,
  удаление хвоста, заголовок/баннер). См. также `АНАЛИЗ_ОШИБОК.md`, раздел 6.
